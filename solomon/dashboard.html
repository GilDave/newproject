구현과 검수는 서로 다른 AI여야 교차 검증이 됩니다.

        
단계마다 AI를 최대 3개까지 둘 수 있습니다. 계획 AI 2·3은 계획을 검토하고(완료 기준만 추가), 구현 AI 2·3은 실패 시 교대하거나(쓰기 가능한 AI) 조언하며(읽기 전용 AI), 검수는 지정한 AI가 모두 통과시켜야 합니다. 범위 검사와 테스트는 AI가 아닌 기계가 판정합니다.

📋 개선 작업으로 이어가기

          
보고서의 구현 방안을 작은 작업으로 나눠 한 번에 하나씩 개선 모드(구현 → 테스트 → 교차 검수)로 실행합니다. 앞 단계를 적용하고 커밋한 뒤 다음 단계를 실행하세요. 구현 AI가 못 하는 일(조사, 화면 확인, API 키 등록)은 「사람이 할 일」로 따로 모읍니다.

          

            🧩 ④ 단계를 실행할 때의 AI (역할)
            

            

            
이 설정은 대시보드의 「역할 배정」과 같은 값입니다. 여기서 바꾸면 대시보드에도 반영되고, 이 브라우저에 기억됩니다. 구현 AI와 검수 AI는 서로 달라야 하고, 로컬 모델은 결정권자에 쓰는 것을 권합니다.

          

          

            🎯 작업을 실행할 프로젝트  
            
보고서가 저장된 프로젝트와 달라도 됩니다. 단계 실행·자동 실행은 여기에 적은 프로젝트의 코드를 바꿉니다(ENA봇 기능이면 ena-bot 폴더).

            

          

          

          

            🌙 자리를 비워도 순서대로 자동 실행
            
체크한 단계를 1단계부터 차례로 만듭니다. 각 단계는 앞 단계 결과 위에서 시작하고, 계획 → 구현 → 테스트 → 교차 검수를 모두 통과해야 다음으로 갑니다. 결과는 새 브랜치에만 쌓이고 원본은 바뀌지 않습니다. 앞 단계가 실패하면 그것에 기대는 단계는 건너뛰고, 3단계 연속 실패하거나 시간이 다 되면 멈춥니다. 끝나면 아이폰 알림(Bark 설정 시)이 옵니다. 돌아와서 관리 탭에서 확인하고 적용하세요.
