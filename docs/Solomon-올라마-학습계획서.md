# Ollama 결정권자 육성 계획서

## 1. 한 장 요약

**목표**: 맥미니의 로컬 Ollama가 3개 AI(Claude·Codex·Antigravity) 위에서 내리는 최종 결정을 점점 더 정확하게 만든다.

**방법**: 처음에는 **그림자 모드**로 운영한다. Ollama는 모든 시도에 대해 판정을 내리지만, 그 판정은 **아무것도 바꾸지 못하고 기록만** 된다. 기록은 기계가 측정한 사실(테스트 통과 여부 등)과 사람이 실제로 한 선택(적용/폐기)에 맞춰 채점된다. 성적이 기준을 넘고 위험한 오판이 충분히 적다는 것이 **숫자로** 확인될 때만 한 단계씩 권한을 올린다.

**판정 결과는 모든 경우의 수로 본다**: 테스트 결과 × 검수 AI 투표 × Ollama 판정 × 정답, 이 조합 전체를 칸으로 나눠 센다 (3장).

**정직한 전제 (중요)**: Ollama의 **모델 가중치는 학습으로 바뀌지 않습니다.** "학습할수록 좋아진다"는 것은 모델을 재학습한다는 뜻이 아니라, 아래 네 가지가 쌓이면서 **같은 모델이 더 좋은 판단을 하게 만드는 것**입니다.

1. 채점된 사례 기록 (무엇을 잘못 판단했는가)
2. 확신도 보정 (자신 있다고 한 판정이 실제로 얼마나 맞았는가)
3. 판단 재료(증거)와 질문 문장의 개선
4. 더 큰/다른 모델과의 비교로 모델 자체를 교체할지 판단

## 2. 원칙

| 원칙 | 내용 |
|---|---|
| 그림자 우선 | 증명되기 전에는 Ollama의 말이 결과를 바꾸지 못한다 |
| 기계가 정답을 정한다 | 테스트 실패·검수 FAIL은 AI 의견이 아니라 측정값이다 |
| 모르면 모른다고 센다 | 아직 사람이 결정하지 않은 건은 "정답 미정"이며 맞음/틀림에 넣지 않는다 |
| 위험한 오판을 따로 센다 | "채택"이라 했는데 정답이 "반려"인 경우만 별도 지표로 본다 |
| 표본이 적으면 결론 금지 | 라벨 30건 미만·채택 판정 10건 미만이면 "데이터 부족"으로만 표시 |
| 실계좌는 건드리지 않는다 | ena-bot은 읽기 전용으로만 평가한다 (코드·서비스·DB 변경 없음) |
| 구독 로그인 CLI·로컬 모델만 | 사용량 과금 API 키는 쓰지 않는다 |

## 3. 판정 결과의 모든 경우의 수

### 3-1. 기록하는 조합

한 번의 판정은 아래 네 가지 축의 한 칸에 들어갑니다.

| 축 | 값 |
|---|---|
| 테스트 | 통과 / 실패 / 생략 |
| 검수 AI 투표 | 전원 PASS / 일부 PASS / 전원 FAIL / 검수 없음 (예: `2/3 PASS`) |
| Ollama 판정 | 채택(ADOPT) / 반려(REJECT) / 사람 확인(NEED_HUMAN) / 무응답(NONE) |
| 정답 | 채택이 옳았다 / 반려가 옳았다 / 미정 |

### 3-2. 한 칸의 해석

| Ollama 판정 | 정답: 채택 | 정답: 반려 | 정답: 미정 |
|---|---|---|---|
| 채택 | **맞음** | **위험한 오판** (가장 중요한 지표) | 집계만 |
| 반려 | **과신중** (기회 손실) | **맞음** | 집계만 |
| 사람 확인 | 사람 확인으로 분류 (맞음/틀림에 넣지 않음) | 사람 확인으로 분류 | 집계만 |
| 무응답 | 무응답으로 분류 | 무응답으로 분류 | 집계만 |

### 3-3. 정답은 어디서 오는가

| 상황 | 정답 | 근거 |
|---|---|---|
| 테스트 실패, 이중 실행 불일치, 검수 FAIL | 반려 | 기계 측정값 |
| 모든 관문 통과 + 사람이 **적용/커밋** | 채택 | 사람의 선택 |
| 모든 관문 통과 + 사람이 **폐기** | 반려 | 사람의 선택 |
| 모든 관문 통과 + 아직 결정 안 함 | 미정 | 아직 모름 |

**한계**: 모든 관문을 통과한 건의 정답은 결국 사람의 선택입니다. 사람이 잘못 적용했을 수도 있습니다. 그래서 채점 결과는 "사람과의 일치율"이며 "절대적 정확도"가 아닙니다. 이 한계는 보고서에도 그대로 표시됩니다.

### 3-4. 칸마다 세는 것

칸별 건수, 전체 정확도(95% 신뢰구간), 위험한 오판 비율(95% 신뢰구간 **상한**), 사람 확인 비율, 무응답 비율, 확신도 구간별 적중률.

## 4. 그림자 모드가 실제로 하는 일 (v1.6.0 구현 완료)

1. 작업실에서 **결정권자를 Ollama로** 두고 **그림자 모드**(기본 체크)를 켠다.
2. 구현→테스트→검수가 평소처럼 진행된다.
3. 시도가 끝날 때마다, **관문 통과 여부와 상관없이** Ollama가 판정한다. 실패한 시도도 판정하므로 사람의 선택을 기다리지 않고도 정답이 있는 사례가 빠르게 쌓인다.
4. 판정은 `arbiter_shadow` 기록으로 저장되고, **결과·재시도·사람 확인 표시에 영향을 주지 않는다.**
5. `solomon shadow --project <폴더>` 또는 대시보드 API(`/api/shadow`)가 위 매트릭스와 지표를 계산한다.

프롬프트에는 측정 근거만 들어갑니다: 범위 검사, 테스트 건수, 이중 실행, 검수 AI별 판정, 변경 규모, 고위험 경로 이름, 변경분 발췌(신뢰하지 않는 데이터로 표시).

## 5. 권한 사다리 (한 단계씩만 올린다)

| 단계 | 권한 | 올리는 조건 | 내려가는 조건 |
|---|---|---|---|
| L0 그림자 | 기록만 | 처음 상태 | — |
| L1 참고 표시 | 화면에 "Ollama 의견" 표시, 따르지 않음 | 라벨 30건 이상 | — |
| L2 사람 확인 줄이기 | 위험 낮은 건의 "사람 확인" 요청을 줄임 | 위험한 오판 상한 ≤ 10%, 채택 판정 10건 이상 | 위험한 오판 1건 발생 시 L1로 |
| L3 반려 권한 | 반려 시 구현자에게 되돌림 (현재 결정권자 동작) | L2에서 안정 운영 | 과신중 비율 급증 시 L1로 |
| L4 채택 권한 | 고위험 경로 외 자동 채택 | 별도 합의 후 | 위험한 오판 1건 발생 시 즉시 L1로 |

- 고위험 경로(주문·리스크·키·설정 등)는 **어떤 단계에서도 사람 확인**입니다.
- 사다리를 올리는 결정은 사람만 합니다. 도구는 "논의해도 된다"까지만 표시합니다 (`ready_to_discuss_promotion`).

## 6. "학습"의 실제 내용

| 단계 | 내용 | 상태 |
|---|---|---|
| P0 | 그림자 기록 + 채점 매트릭스 | **구현됨 (v1.6.0)** |
| P1 | 데이터 쌓기: 작업을 평소처럼 돌리면서 라벨 30건 이상 확보 | 사용자 운영 |
| P2 | 사례 기억: 틀린 판정 사례를 모아 비슷한 상황에서 질문에 함께 보여줌 (few-shot) | 계획 |
| P3 | 확신도 보정: "0.8"이 실제 80%인지 점검해 채택 기준(현재 0.6)을 데이터로 조정 | 계획 |
| P4 | 모델 비교: 더 큰 모델(14B급)을 같은 사례로 채점해 교체 여부 판단 | 계획 |

모델 파인튜닝은 하지 않습니다. 사례가 수백 건에 못 미쳐 과적합 위험이 크고, 맥미니에서의 운영 부담 대비 이득이 불확실하기 때문입니다. P2·P3로 먼저 개선 여지를 확인합니다.

## 7. ena-bot 필터 평가 (읽기 전용, v1.6.0 구현 완료)

봇이 이미 쓰는 Ollama 필터(진입 신호의 반대 방향이면 거부)가 실제로 도움이 되는지 **봇을 건드리지 않고** 측정합니다.

- 입력: `bot.db`의 `events`(kind=`llm`)를 `mode=ro`로 열기 + 캔들 CSV.
- 반사실 결과: 각 판정 시점에 진입했다면 N개 캔들 뒤 수익률(수수료 차감). 막은 진입이 손실이었으면 "잘 막음", 허용한 진입이 이익이었으면 "잘 허용".
- 필터 꺼짐 비율: 응답 불가/형식 오류(`llm_unavailable_or_invalid`)로 필터가 사실상 꺼져 있던 비율. (현재 설정은 실패 시 **허용** 이므로 이 비율이 높으면 필터가 없는 것과 같습니다.)
- 확신도 구간별 막은 건의 적중률, 필터 없음 기준선 승률.

```
solomon shadow --bot-db /Users/dave_gil/00.Claud/01.ena-bot/data/bot.db \
               --candles /Users/dave_gil/00.Claud/01.ena-bot/data/ENAUSDT_3m.csv
```

**한계**: 종가 기준 근사이며 봇의 실제 청산 규칙·체결가와 다릅니다. 표본 30건 미만 칸은 결론이 아닙니다. 이 결과로 봇 설정을 바로 바꾸지 않고, 개선 후보(필터 응답 형식 고정, 확신 임계값 보정, 실패 시 동작 재검토)를 Solomon 파이프라인으로 만들어 **사람이 적용**합니다.

## 7-2. 봇 연구실 탭 (v1.7.0 구현 완료) — 모든 것을 대시보드에서 자동으로

실제 봇은 3분봉 LLM 필터가 아니라 **4시간 간격 추세 추종 봇**입니다 (이벤트: 예측 `ml2_pred`, 뉴스 점수 `news_score`, 그림자 `ml_shadow`, 추세 `trend_cycle`). 그래서 평가 대상은 예측과 뉴스 점수입니다.

| 자동으로 하는 일 | 주기 | 봇에 미치는 영향 |
|---|---|---|
| 최신 가격 받기(별도 폴더) + 예측·뉴스 점수 채점 + 기록 | 6시간 | 없음 (DB 읽기 전용) |
| 3개 AI가 개선 방법을 분석(읽기 전용) | 24시간 | 없음 (코드 변경 없음) |
| 봇 서비스·오류·마지막 판단 시각 확인 | 화면 열 때/15초 | 없음 (읽기만) |
| 모든 실행에 보호 구역 적용 + 결정권자 그림자 판정 | 항상 | 주문·리스크·키·데이터·서비스는 AI가 변경 불가 |

아직 없는 것: **수익률 관문**(표본 밖 워크포워드로 합격 판정). 이것이 생기기 전까지 코드 변경 후보는 사람이 직접 검토합니다.

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 표본이 적은데 결론을 내림 | 최소 표본 미만이면 "데이터 부족"만 표시 |
| 사람이 잘못 적용한 것이 정답이 됨 | 한계를 보고서에 명시, 기계 측정 정답과 사람 정답을 분리해 표시 |
| Ollama와 봇이 같은 모델을 다른 옵션으로 호출해 서로 밀어냄 | Solomon 전용 모델 이름(별칭)을 따로 둠 (다음 단계) |
| 느린 응답이 작업을 지연 | 그림자 모드는 판정 실패 시 건너뜀, 결과에 영향 없음 |
| 봇 데이터 손상 | DB는 읽기 전용으로만 열고 결과는 별도 출력, 테스트로 변경 없음 확인 |
| 같은 모델이 만든 것을 같은 모델이 판정 | 결정권자는 구현자와 달라야 함 (이미 강제) |

## 9. 사용 방법

**대시보드(권장)**: 작업실 → 역할 배정에서 👑 결정권자 = Ollama → **그림자 모드 체크(기본 켜짐)** → 평소처럼 실행.

**명령 (붙여넣기)**

```
cd /Users/dave_gil/00.Claud/00.Solomon && .venv/bin/solomon shadow --project /Users/dave_gil/00.Claud/00.Solomon
```

결과는 JSON입니다. 보는 곳: `cells`(모든 조합 칸), `accuracy`, `danger`(위험한 오판), `note`(데이터 부족 여부), `ready_to_discuss_promotion`.
